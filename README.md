ЛР3: магнитометр LSM9DS1/LSM9DS0, OLED SSD1306, I²C, UART и клиент ПК.

## Сразу запустить без платы

Нужны Git, Python **3.10+** и интернет для первоначальной установки зависимостей. Все команды выполняются из корня клона. Писать или менять код не требуется.

```sh
git clone https://github.com/tteemma/sdk-compass-labs-3-4.git
cd sdk-compass-labs-3-4
python3 run.py --lab 3 --demo
```

В Windows использовать `py -3` вместо `python3`. Скрипт сам создаёт `tools/venv` и устанавливает зависимости. Интерфейс работает в Terminal/Windows Terminal (76×19 символов или больше). DEMO явно обозначен: это синтетические данные, не измерения платы. Для ЛР4 заменить `--lab 3` на `--lab 4`.

## Запустить с платой

1. Установить **OpenOCD**: macOS `brew install open-ocd`; Ubuntu/Debian `sudo apt install openocd`. В Windows установить OpenOCD и добавить его `bin` в PATH либо задать переменную `OPENOCD` с полным путём к программе.
2. Подключить **DBG USB**. Для встроенного FTDI в Windows JTAG Interface 0 должен использовать WinUSB (Zadig); UART Interface 1 — драйвер виртуального COM-порта. В Linux пользователю нужны права на USB-адаптер и последовательный порт (обычно группа dialout); при необходимости применить правила доступа из документации стенда.
3. Сверить модель процессорного модуля: `.407` или `.427`. По умолчанию `.427`.
4. Найти порт и прошить готовый образ:

```sh
python3 run.py --list-ports
python3 run.py --lab 3 --mcu 427 --flash --port /dev/cu.usbserial-ИМЯ
# Windows:
# py -3 run.py --lab 4 --mcu 407 --flash --port COM5
# Linux: --port /dev/ttyUSB1 (фактический номер проверить)
```

Скрипт проверяет SHA256 прошивки, записывает ELF, проверяет Flash, выполняет reset и запускает клиент. **Компилятор для этого не нужен.** Для одной записи использовать `--flash-only`. Если плата уже прошита: `python3 run.py --lab 3 --port COM5`. UART 115200 8N1 задаётся автоматически. Если выполнение не началось после прошивки, нажать RESET. Не открывать UART одновременно в другой программе.

Без подключённой платы проверить комплект можно так:

```sh
python3 run.py --verify
python3 run.py --lab 4 --mcu 427 --check-config
```

`--check-config` только разбирает конфигурацию OpenOCD и не обращается к адаптеру. Проверить `.407`: `--mcu 407`.

## Управление

X/Y/Z или Left/Right — ось; +/- либо Up/Down — изменение на 1%; PgUp/PgDn — на 10%; Enter — применить; R — вернуть 100%; Q — выход. Коэффициенты 0…200%. Начальные — 100%.

Клиент показывает поле XYZ в µT, стрелку, угол, применённые коэффициенты и состояние датчика/OLED. При открытии отправляет PING и ждёт PONG. UART журналируется в `uart.jsonl`: UTC-время, TX/RX, исходные байты hex, текст, флаг demo. Задать другой файл: `--log session.jsonl`.

Плату держать горизонтально. X+ — верх указателя, Y+ — правая сторона. Реальную ориентацию осей нужно сверить поворотом платы; металл и магниты меняют локальное поле. При нулевом горизонтальном поле направление неопределённо.

## Что входит

- `ЛР3/Compass_LR3_V2`, `ЛР4/Compass_RTOS_LR4_V2`: полные проекты STM32CubeIDE/Makefile, startup, linker script, OpenOCD, HAL/CMSIS; ЛР4 включает FreeRTOS V11.2.0. Submodule и загрузка пакетов CubeMX не требуются.
- `Debug/*.elf`, `*.hex`, `*.bin`: готовые образы для STM32F407 и STM32F427.
- `client`: клиент ПК, зависимости; `tests`: тесты C и Python, имитаторы устройств.
- Отчёт PDF на 15 страниц для каждой работы, редактируемый `report.md`, инструкции и `ПРОВЕРКА_НА_ПЛАТЕ.md`.
- `artifacts`: результаты программной проверки и контрольные суммы.
- `tools`: исходники генератора отчётов и логотип. Для генерации на macOS нужны reportlab и системные Times New Roman; `make_reports.py` создаёт оба отчёта.

## Пересобрать и проверить исходники

Установить STM32CubeIDE или официальный Arm GNU Toolchain **arm-none-eabi с newlib**, Make и Clang. Homebrew arm-none-eabi-gcc без newlib недостаточен. В Windows использовать среду Make из IDE/MSYS2 либо Linux/WSL. Проекты размещать в пути без пробелов.

```sh
make -C ЛР3/Compass_LR3_V2 MCU=STM32F427xx
make -C ЛР4/Compass_RTOS_LR4_V2 MCU=STM32F407xx
python3 run.py --setup
sh ЛР3/test.sh
sh ЛР4/test.sh
```

Makefile ищет компилятор в STM32CubeIDE и PATH; нестандартное расположение задаётся `CROSS=/путь/arm-none-eabi-` или `IDE_APP=/путь/STM32CubeIDE.app`. В IDE импортировать как Existing Projects. После пересборки образы могут отличаться по SHA256: `run.py --flash` намеренно принимает только исходные проверенные образы; для собственной сборки использовать `ЛР3/flash.sh` или `ЛР4/flash.sh`.

Для проверки C нужны Clang и ASan/UBSan; PTY-тесты клиента рассчитаны на macOS/Linux. Windows для тестов — через WSL. Клиент Windows работает через windows-curses. Тестирование аппаратуры не заменяется имитацией.

## Статус и лицензии

Проверены ARM-сборки, логика C с ASan/UBSan, имитаторы I²C/OLED, клиент через PTY, контрольные суммы и конфигурации OpenOCD. Физическая плата пока не проверена: запуск, ориентация осей и реальная частота ≥20 FPS требуют стенда. Расчётный период обновления — 40 мс (25 FPS); в ЛР4 есть счётчик 00…99. Чек-листы находятся в папках работ.

Библиотечные лицензии сохранены в Drivers и Middlewares. Точные commit SHA зависимостей — Drivers/versions.json. Готовые отчёты включены; исходная методичка стороннего авторства не переиздаётся в репозитории.
