## Сборка и загрузка

```sh
make -C Compass_LR3_V2
./flash.sh --check-config  # только разбор конфигурации, без платы
./flash.sh                 # .427: запись, verify, reset
MCU=STM32F407xx ./flash.sh # .407
```

Проект импортируется в STM32CubeIDE как Existing Project. Отдельная генерация CubeMX не нужна. Готовые файлы в `Compass_LR3_V2/Debug`: имя включает HAL/REGISTER и STM32F407xx/STM32F427xx. После смены модели всегда прошивать соответствующий ELF. JTAG: встроенный FTDI, разъём DBG USB. Отладочный сервер: `./flash.sh --debug`; GDB: target remote localhost:3333, monitor reset halt, load, break main, continue. Если reset не запустил программу — нажать RESET.

Проверки без платы: `./test.sh`. На другом компьютере указать HOST_CC и PYTHON при необходимости. Проверки не подменяют испытаний из ПРОВЕРКА_НА_ПЛАТЕ.md. Отчёт PDF и report.md лежат рядом.

## Клиент: 115200, 8N1

```sh
../tools/venv/bin/python client/client.py /dev/cu.usbserial-ИМЯ --log uart.jsonl
../tools/venv/bin/python client/client.py --demo --log demo.jsonl
```

Настоящий COM-порт задаётся аргументом; при открытии немедленно отправляется PING, ожидается PONG COMPASS 1. Обновления идут автоматически. Клавиши X/Y/Z или Left/Right выбирают ось; +/- и Up/Down меняют коэффициент на 1%, PgUp/PgDn — на 10%. Enter отправляет все три коэффициента, R отправляет 100/100/100, Q закрывает порт. Интерфейс показывает применённые коэффициенты отдельно от редактируемых. Логи TX/RX: JSONL с UTC-временем, исходными байтами hex и текстом. Не открывать порт одновременно другой программой.

Показываются компоненты в µT, направление поля, состояние датчика и OLED, кадры и интервал. При SENSOR ERROR или нулевом горизонтальном поле направление не показывается. При прекращении телеметрии клиент показывает STALE. Коэффициенты 0…200%, начальные 100%, действуют до следующей команды или RESET; отдельная перезагрузка не требуется.

I²C1 PB8 SCL / PB9 SDA AF4 open drain, 400 кГц. Используются внешние подтяжки стенда. OLED 7-bit 0x3C (байт адреса 0x78), RESET через P0 расширителя 0x70 (0xE0). Датчик определяется WHO_AM_I: LSM9DS1 0x3D по адресу 0x1C/0x1E; LSM9DS0 0x49 по 0x1D/0x1E. Частота измерений 80 Гц DS1 / 100 Гц DS0, BDU включён. Шкала DS1 ±4 gauss, DS0 ±2 gauss.

Направление вычисляется в системе осей датчика: X+ соответствует верху указателя, Y+ — правой стороне. Плата должна лежать горизонтально. Проверить реальную ориентацию осей по маркировке и разворотом стенда; возле корпуса ПК и магнита показывается локальное поле. Компенсация наклона, магнитного склонения и hard/soft iron не предусмотрена заданием. Подтвердить направление стрелки экспериментально перед защитой. На OLED также показаны компоненты, масштабы, heading и циклический счётчик F:00…99. Единица X/Y/Z на OLED — µT.

## Протокол v1

ASCII, LF на входе, CRLF на выходе. Команды ограничены 79 байтами.

- `PING` → `PONG COMPASS 1`.
- `GET` → одна строка DATA.
- `SCALE X Y Z` (целые 0…200) → `OK SCALE` или `OK SCALE QUEUED`.
- Ошибка → `ERR COMMAND`. Некорректная команда не меняет настройки.
- Автоматически каждые ~100 мс: `DATA tick Bx By Bz heading sx sy sz sensor_ok oled_ok sensor_id frames frame_ms`.

Bx/By/Bz — целые nT после масштабирования; heading — сотые градуса 0…35999, -1 при неопределённом направлении; tick — мс HAL; flags 0/1; sensor_id — десятичный WHO_AM_I; frames — число полностью переданных кадров, frame_ms — интервал последних окончаний передачи. При sensor_ok=0 прежние компоненты не являются актуальными. Между физическими обновлениями повторяется последнее измерение.

OLED — 1024 байта, передача разбита на 32 блока по 32 байта. Расчётный период 40 мс (25 FPS). Расчётное время передачи при 400 кГц: 32×(1 адрес+1 control+32 data)×9/400000 ≈24,48 мс плюс START/STOP и программные затраты. Измерять реальные FPS по разности frames/tick за несколько секунд, а не только по одному frame_ms. При неисправности I²C/дисплея требование FPS не считается выполненным. Ошибки не останавливают UART, повторная инициализация выполняется раз в секунду.
